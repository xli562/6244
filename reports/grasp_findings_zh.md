# 让模型按物体选抓法：碗、书与六项新任务

**两项修复都成功了。** 原来各 1/50 的“关抽屉后把碗放上柜顶”和“把书放进收纳盒右格”，在本轮留下的 40 个摆放上分别达到 **40/40**。两家模型、两种编程方式都取得这个结果。到六项没调过的新任务，Codex 的顺序计划和自由改写同为 236/300；Claude 的自由改写为 244/300，顺序计划为 186/300。新抓法能迁移，最佳成绩出现在允许模型看情况改抓法、也自己选物体的程序上。

## 两个 1/50 是怎么修的

碗、书上轮都是 1/50。这次每题拿 6 个摆放调动作、4 个摆放验证，最后 40 个在本轮不参与调试。Codex 和 Claude 分别编程。无论用顺序计划还是自由改写，两家在这 40 个摆放上都是碗 **40/40**、书 **40/40**。松开夹爪、抬手并等待 40 个控制步后，80 次成功都保持住了。把同一份顺序计划的抓放动作换回旧版，碗只剩 1/40，书是 0/40，与上一轮冻结计划在这 40 个摆放上的结果一致。

**碗需要抓碗壁，也需要正确地靠近它。** 新版把上轮 Claude 已经跑成功的碗沿动作做成了两家都能调用的抓法。机械臂先在碗沿上方对正，再下降、合拢、小幅提起，确认碗跟着走后才搬到柜顶。在同样的 10 个调试和验证摆放上，只换回旧版的碗沿抓点，仍是 10/10；保留新抓点，只换回旧版的靠近和提起动作，就成了 0/10，10 次都没有把碗提起超过 2.5 厘米。可以把改善归到这一段动作，目前的对照无法把功劳细分到其中某一个控制步。

**书原来抓得太低。** 在这项模拟任务里，书竖放，物体的位置坐标靠近书底。新抓法读取长方体的可见几何，朝书的窄边合拢夹爪，在书身较高的位置抓住，确认提起后再把书身中心对准格口。保持其余动作相同，只把抓点降回旧高度，10 次全部失败，书最多升高 9 毫米。反过来，单独关闭拿书时的转腕，或单独关闭进格前的转腕，各自仍是 10/10。这批数据支持“抓取高度很重要”，单独给转腕记涨分缺少依据。

## 怎样保证比较公平

两种方法的模型、推理设置、旧程序、动作接口、物体目录、英文任务、起始摆放、500 步上限和判分器一致。提示词只有最后一句不同：一组要求写顺序计划并明确每件物体的抓法，另一组允许完整自由改写，也能随时调用相同的新抓法。抓法包括抓碗沿、夹薄物体和原有普通抓放。每个模型对每条指令、每种方法只实际调用一次 CLI，生成的程序对全部摆放复用。还有一组不额外请求模型，直接重放顺序计划，把显式抓法换回旧动作，用来单独检查执行器的贡献。所有实验都在 MuJoCo 内完成，夹爪靠物理接触搬运，抓法可以读取模拟器给出的几何尺寸和姿态。

六项迁移任务在调试前确定，未用于此前各轮调试，冻结动作和提示词后才为它们请求程序。300 个起始状态均不完全相同，与之前 24 项任务的初态没有完全相同的向量。本轮两项修复和六项新题的 16 个任务/状态文件均已逐一核对公开来源的 SHA-256。[任务和数据清单](../sim/data/libero_grasps.json) · [固定版本的上游 LIBERO 任务](https://github.com/Lifelong-Robot-Learning/LIBERO/tree/8f1084e3132a39270c3a13ebe37270a43ece2a01/libero/libero/bddl_files/libero_90)

## 六项新任务的成绩

每项 50 个官方摆放。每个格子依次是 Codex 和 Claude 的成功数。例如“39 / 47”表示两家分别做对 39 次和 47 次。全部任务条件都要满足才算成功。

| 任务 | 顺序计划 | 自由改写 | 同一顺序计划换回旧抓放 |
| --- | ---: | ---: | ---: |
| 黑碗放上盘子 | 39 / 39 | 39 / 47 | 7 / 10 |
| 前碗叠在中碗上 | 47 / 47 | 47 / 47 | 16 / 21 |
| 书放进收纳盒左格 | 50 / 50 | 50 / 50 | 27 / 27 |
| 左边的书放到架顶 | 50 / 0 | 50 / 50 | 50 / 0 |
| 奶油奶酪放入托盘 | 50 / 50 | 50 / 50 | 50 / 50 |
| 前面的黄油放进上层抽屉再关上 | 0 / 0 | 0 / 0 | 0 / 0 |
| **官方成功，各 300 次** | **236 / 186** | **236 / 244** | **150 / 108** |
| **松手抬起后仍成功，各 300 次** | **235 / 185** | **235 / 243** | **147 / 105** |

**新抓法帮到了什么。** 在相同顺序计划上，把显式选抓法的调用替换为原来的普通抓放，Codex 合计从 236 降到 150，Claude 从 186 降到 108。最清楚的三个例子是黑碗上盘、两碗堆叠、书入左格。书入左格的新抓法两家都是 50/50，换回原动作两家都是 27/50。两碗堆叠官方记 47/50，松手再检查还剩 46/50。这是官方总数与稳定成功总数相差一次的来源。

**Claude 的 58 次差距集中在两题。** 从“左边的书放上架顶”的动作记录看，顺序计划每次都抓了右边那本黄书，50 次都把它提起来，按题意却是 0/50。自由改写识别出左边标记对应的那本黄书，50/50。为核验原因，我保留 Claude 的原顺序计划，只把“用固定的世界坐标方向猜左边”换成“选离可见左侧起始区域最近的书”，相同 50 次就从 0 到 50，松手后 50 次仍然成功。Codex 在这道题两种方法原本就是 50/50，换回原抓放也能得满分。这里起决定作用的是选哪本书。[只改选书的程序](../runs/object_grasps_01/posthoc/change_book_selector/policy.py)

另 8 次来自黑碗上盘。Claude 顺序计划和自由改写都先夹碗沿，39 个相同的摆放第一次就成功了。剩下 11 个摆放，顺序计划又用同一抓法，自由改写改试普通抓放，额外救回 8 个。保留顺序计划其余代码，只把第二次重试改成普通抓放，成绩也从 39/50 到了 47/50。这两项原因核验都是看完测试后做的，没加回六题主成绩。[只改第二次抓法的程序](../runs/object_grasps_01/posthoc/change_second_grasp/policy.py)

**两类没有涨分的任务。** 奶油奶酪进托盘各组原本就有 50/50，程序选了普通抓放。黄油放进抽屉再关上，各组都是 0/50。两家都选中了题目指定的前方黄油，也都选了普通抓放；在顺序计划的失败记录里，两家各 50 次都没有测到黄油被提起超过 2.5 厘米。Codex 有 22 次在结束时关上了抽屉，但没有一次把黄油放进去。这次增加的碗和书的抓法尚未解决这类低矮物体的抓取。

每题每种方法只生成一份程序，因此这些数字说明的是本轮冻结程序的表现。完整验证了 32 次 CLI 调用记录、各组输入一致性、逐个摆放的官方成功和松手后结果；两组对六条新指令的全部程序都实际进入了模拟器。[本轮凭证包](grasp_evidence.zip) · [逐任务汇总](../runs/object_grasps_01/summary.json) · [复现步骤](../docs/simulator_experiments.md)

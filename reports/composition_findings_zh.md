# 两把壶、盘子右边，以及五项从没调过的任务

**两项指定故障都修出了可重复的提升。** 在本轮没有用于调试或选版的摆放上，两家都是“两把壶上炉”40/40、“杯子上盘且布丁放右边”35/40。另找的五项新任务上，两家新版都拿到官方 94/250。给旧系统同样一次调用模型的机会，Codex 是 50/250，Claude 是 99/250。新版对 Codex 有额外收益，Claude 的自由改写在一项白碗任务上多做对了 5 次。这里测的是每个模型每题生成一次程序后的表现。

| 原来 0/200 的四项任务 | 本轮评估摆放 | 旧 Codex / 旧 Claude | 新 Codex / 新 Claude |
| --- | ---: | ---: | ---: |
| 两把摩卡壶都放上炉 | 40 | 0 / 0 | 40 / 40 |
| 白杯上盘，布丁放到盘子右边 | 40 | 0 / 0 | 35 / 35 |
| 奶酪和黄油都放进篮子 | 50 | 0 / 0 | 35 / 35 |
| 杯子放进微波炉，再关门 | 50 | 0 / 0 | 0 / 0 |
| **合计** | **180** | **0 / 0** | **110 / 110** |

从上一轮 200 个摆放中拿出了 20 个调试和验证，表里只列余下的 180 个。两家在布丁题余下的 5 次失败里，布丁都已经放对，杯子没能留在盘子上。按新执行器成功的上述 110 次，统一松手、抬起机械臂并等待 40 步之后，两个模型都仍然有 110 次满足全部条件。

## 两个零分分别是怎么修好的

**两把壶。** 这道题开局时炉子已经打开。上轮报告把最终的炉子状态算成了机器人的动作，这里更正。旧 Claude 在一个典型失败里只尝试搬第一把，旧 Codex 搬完第一把后，还可能在第二把上抓空并用完 500 步。新接口要求模型把每一件要搬的东西和目的地写出来。两个模型独立生成的计划都列出了两把壶。执行器为它们在炉面上留出两个相距 9 厘米的落点，每次先小幅提起检查是否抓牢，抓空时换抓点。

在同样 10 个开发和验证摆放上，完整做法成功 10 次。只把两个落点改回同一个炉心，其他动作照旧，成功数掉到 0。保留两个落点、把抓点固定在壶中心，则为 4/10。从这组对照看，给第二把壶留位置解决了最大的障碍，换抓点也有贡献。

**杯子上盘，布丁放在盘子右边。** 旧 Codex 在这条指令上没发出动作。旧 Claude 有时能把杯子放上盘，仍会把两步中的一步做错。新计划明确写了两个不同的终点，杯子去盘子，布丁去盘右侧的桌面区域。在同样 10 个摆放上，给旧的默认搬运动作换上正确计划，布丁有 7 次到位，两步同时完成 0 次。完整执行器让布丁 10 次到位，两步同时完成 9 次。

杯子怎么放也解释了差别。夹爪抓在杯沿时，杯子中心和夹爪中心有一段距离。新执行器提起杯子后量这个偏移，再决定在哪里松手。只去掉这一步，其余代码和测试摆放完全相同，两步同时完成的次数从 9/10 掉到 4/10，布丁仍有 10/10 到位。也就是说，这一次掉分的确发生在杯子上。

## 怎样测迁移

两项修复各用了 6 个摆放调试、另 4 个验证，剩余 40 个只用于本轮评估。原先 0/200 中的另外两项任务沿用原样复测。它们在上一轮已经公布过成绩。

真正的迁移测试另外选了 5 条 LIBERO-90 指令，每条有 50 个官方初始状态。这些指令没有参加本轮或上一轮的调试，本轮在调试前就固定了名单。然后冻结共用提示词、执行器和两个模型各自的旧程序。新题到来时每个 CLI 只看任务文字、物体和区域名，编一次计划，对全部 50 个摆放复用。代理看不到测试分数、目标判定或示范轨迹。任务定义和官方初态来自[固定版本的 LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO/tree/8f1084e3132a39270c3a13ebe37270a43ece2a01/libero/libero/bddl_files/libero_90)。

同一个模型有四项可比较的结果。旧冻结程序不新增模型调用。另一个对照沿用上轮的适配方式，给模型同一条新指令、物体名称和旧程序，让它自由改写一次。第三项用新模型计划配旧的默认搬运动作。第四项是新计划和新执行器。后三项在每个任务的模型调用次数可比，新计划的两个执行版本共用同一次调用。两家用各自上轮的模型和推理设置，所有方法的机器人都限 500 步。


## 五条新指令的成绩

各题 50 个摆放。下表是同时满足全部官方目标的次数。两家模型各自为新接口生成计划，这批任务在新版下恰好取得了相同的逐题成绩。

| 新任务 | 旧冻结 Codex / Claude | 各自自由改写一次 Codex / Claude | 新计划配旧搬运动作 Codex / Claude | 完整新版 Codex / Claude |
| --- | ---: | ---: | ---: | ---: |
| 白碗放在盘子右边 | 0 / 0 | 0 / 49 | 22 / 22 | 44 / 44 |
| 红杯放在收纳盒右边 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| 黄油放进托盘 | 0 / 50 | 50 / 50 | 50 / 50 | 50 / 50 |
| 叠碗（原始文字和裁判有冲突） | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| 关下抽屉，再打开上抽屉 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| **合计，每个模型各 250 次** | **0 / 50** | **50 / 99** | **72 / 72** | **94 / 94** |

**迁移最清楚的是白碗。** 新计划找到了盘子右侧的桌面区域，旧默认动作已经能做对 22/50，新执行器把同一份计划提高到 44/50。黄油进托盘只需要明确物体和容器，换执行器没有额外涨分。新版成功的 94 次，在松手抬起后的复查中也全部成立。给两家各跑一次的成绩不能用来判断哪个模型普遍更强。

**两个真正的缺口。** 收纳盒的“右侧桌面”和“右边的格子”同时出现在物体目录里，两家都把红杯送去了盒内右格。后续核对上游原文发现，这题实际给模型的英文写的是“右格”，官方裁判和任务名要求的却是“右侧桌面”。原来把这次选格子归因为模型误解并不准确。遇到先关后开的抽屉指令，两家都调用了原来的控制程序，新执行器没有提供开、关抽屉的动作。这两个零分对应不同的修复方向，一个是区分内外，另一个是补全能执行的动作。

**叠碗的零分有数据原因。** 官方英文说“把中间的碗叠在前面的碗上”，同一个文件里的判分条件却要求叠在后面的碗上。保留官方 0/50 后，我又对相同冻结程序和初态重放，只额外检查一次“是否叠在前碗上”。新版 Codex 和 Claude 各有 **50/50** 在结束时满足英文指令。这是单列的核验，没有加进 94/250。[上游原始指令、摆放定义及判分条件](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/8f1084e3132a39270c3a13ebe37270a43ece2a01/libero/libero/bddl_files/libero_90/KITCHEN_SCENE2_stack_the_middle_black_bowl_on_the_back_black_bowl.bddl) · [逐次附加核验](../runs/composition_01/language_audit.json)

两个模型在五条新指令上各实际调用了 5 次 CLI 生成短计划。日志中的调用耗时合计约为 Codex 28 秒、Claude 25 秒；让它们自由改写整份程序分别约为 317 秒、410 秒。这是本机这一轮的调用计时，不包含仿真，不能推算费用或给出稳定的速度倍率。所有运行都在模拟器里完成，策略能读取物体位置和区域名称。逐次成绩、两家模型实际输出的代码、提示词与冻结记录均已保存。[实验凭证包](composition_evidence.zip) · [复现步骤](../docs/simulator_experiments.md)

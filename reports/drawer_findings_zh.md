# 红杯、双抽屉与六项新任务的模拟器实测

**两项原来的零分都有提升。** 40 个本轮留出的摆放里，Codex 和 Claude 各自做到了红杯 24/40、双抽屉 40/40。迁移到六项新任务后，新计划各得 62/300。给自由改写同样一次调用和同样一套动作，Codex 也是 62/300，Claude 则达到 107/300。短计划帮助模型按文字区别盒内和盒外，但默认抓放会错过更适合特定物体的做法。

## 两个零分是怎么来的

**红杯这道题有两条不一致的指令。** 项目展示的任务名和官方裁判都要求把红杯放在收纳盒右侧的桌面上。上游实际交给模型的英文却写着 *right compartment*，意思是右格。上一轮说模型误解了“右边”，这个归因应当更正。这里用用户给出的“收纳盒右边”作为修复题文字，同一轮里所有新生成的方法都读到它；原始英文和新文字都保存在输入记录里。六项新测试完整保留上游英文。[上游红杯任务文件](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/8f1084e3132a39270c3a13ebe37270a43ece2a01/libero/libero/bddl_files/libero_90/STUDY_SCENE3_pick_up_the_red_mug_and_place_it_to_the_right_of_the_caddy.bddl)

把文字澄清之后，连旧提示词也能让两个模型选对桌面。剩下的问题是杯子能否拿稳。新版让计划分别表达“盒外同侧的桌面”和“盒内同侧的格子”，并按杯子自身朝向选上部抓点。下面 40 个摆放都没用于本轮调试或选版。

| 修复题，每项 40 个摆放 | 上轮冻结计划 | 旧提示词重新读本轮指令 | 新计划和新动作 | 底层接口自由改写 Codex / Claude | 同样新动作自由改写 Codex / Claude |
| --- | ---: | ---: | ---: | ---: | ---: |
| 红杯放盒子右侧 | 0 | 15 | 24 | 0 / 3 | 24 / 3 |
| 先关下抽屉再开上抽屉 | 0 | 0 | 40 | 0 / 0 | 40 / 40 |

表中只列一个数的列表示两个 CLI 各自的成功数相同。旧提示词红杯的 15 次官方成功里有 14 次在松手等待后仍成立，新版的 24 次全部成立。剩余 16 次都耗尽 500 个控制步，其中 11 次确实提起过红杯超过 2.5 厘米，却没把它留在目的地。看这批记录，继续修改“右边”的提示词很难解决这些抓放失败。

**双抽屉缺的是能执行的动作。** 旧计划直接调用旧程序，新版把要求编成两次抽屉操作。机械臂依据柜子朝向定位把手，斜着手腕从前面推回下抽屉，再调整腕姿，夹住上层把手往外拉。每次都通过夹爪施力和物理接触完成。两家各 40 次都先满足“下层已关”，再满足“上层已开”，松手、抬起、等待后两层仍然正确。只把腕姿改回原位，其余动作不动，独立验证的 4 次从 4/4 掉到 0/4。把同一抽屉动作开放给自由改写，两家也都是 40/40。这项提升可以归到新动作本身。

## 迁移测试怎样比

调试开始前就固定了另 6 条 LIBERO-90 指令，各取官方全部 50 个起始摆放。300 个初始状态互不完全相同，与先前 18 项任务的初态也没有完全相同的向量。两项修复各用初态 0–5 调试、6–9 验证、10–49 计分；这两项上一轮已有整体成绩，六项新题才是本轮的迁移测试。任务定义和初态文件已与固定版本的上游逐个核验。[公开数据清单与校验值](../sim/data/libero_drawers.json)

每项新任务让 Codex CLI 和 Claude Code CLI 分别生成程序。每个模型每种方法只调用一次，程序冻结后独立做 50 个摆放，不用测试反馈再改。底层自由改写沿用上轮的运动、夹爪和搬运接口；同动作自由改写还得到新版的空间关系、抓放和抽屉动作，可以自行决定要不要用。新版则明确要求写短的顺序计划。三种方案用同一份英文和物体名目录、同一模型设置和同一批初态。程序在模拟器中可读取状态，不使用测试判定、真人示范或机械臂实机。


## 六项新任务的成绩

每个格子的两个数依次是 Codex 和 Claude 的成功次数。例如“49 / 31”表示两家分别做对了 49 次和 31 次。

| 新任务，每项 50 个摆放 | 新版顺序计划 | 自由改写（底层接口） | 自由改写（同样的新动作） |
| --- | ---: | ---: | ---: |
| 黄白杯放收纳盒右侧桌面 | 50 / 50 | 49 / 31 | 50 / 35 |
| 书放进收纳盒右格 | 1 / 1 | 0 / 0 | 1 / 3 |
| 打开木柜下抽屉 | 0 / 0 | 0 / 0 | 0 / 0 |
| 打开上抽屉并把碗放进去 | 10 / 10 | 0 / 0 | 10 / 19 |
| 关上抽屉并把碗放到柜顶 | 1 / 1 | 0 / 50 | 1 / 50 |
| 打开微波炉 | 0 / 0 | 0 / 0 | 0 / 0 |
| **官方成功，每个模型各 300 次** | **62 / 62** | **49 / 81** | **62 / 107** |
| **松手、抬起并等待后仍成功，每个模型各 300 次** | **62 / 62** | **47 / 73** | **62 / 95** |

**能迁移的是盒外放杯。** 换房间、换黄白杯，两家新版都是 50/50，松手后仍然 50/50。书进右格这道题两家也都选对了内部区域，但都只有 1/50 成功。对失败的 49 次，新版至少有 20 次连 2.5 厘米都没把书提起来。选对位置和拿稳物体是两件可以分别检查的事。

**抽屉的迁移取决于柜子和后续动作。** 指定故障用的是白柜。换成木柜，打开底层抽屉仍是 0/50；在一个典型失败中，两次抓拉后测得的抽屉位移约为 0 毫米和反向 2 毫米。记录表明把手没被有效带动。木柜上层要好得多：“开上层放碗”有 47/50 次在结束时上层已开，只有 10/50 同时把碗放进去了。“关上层、碗放柜顶”则 50/50 都关好了抽屉，只有 1/50 把碗放对。微波炉门需要绕铰链转动，两家的新计划都交回旧程序，仍然是 0/50。

**为什么 Claude 自由改写反而赢。** 最大差别就在“关抽屉，碗放柜顶”。新版统一的抓取动作有 49/50 次没把碗提起超过 2.5 厘米。Claude 的改写调用了它已有的碗沿抓法，允许尝试不同位置。为检验原因，我额外重放了这 50 次：保留新版关抽屉的代码，只把之后放碗的一段替换成 Claude 的自由改写版本，结果从 **1/50 到 50/50**，松手后的 50 次也都成立。这是看完测试后做的原因核验，没有计入新版的 62/300。[只替换放碗动作的程序](../runs/grounded_drawers_01/bowl_diagnosis/swap_place_only.py) · [逐摆放对照](../runs/grounded_drawers_01/bowl_diagnosis/posthoc.json)

**一项计分说明。** 在“书进右格”的底层自由改写组，Claude 唯一一次返回的程序试图读取私有缓存，没通过原有的程序校验。这一组 50 次计为失败，保留了原回复代码和原因，没有再向模型要第二份答案。提供同样新动作的自由改写组成功生成了合法程序并完成了 3/50。每题每个模型每种方法只生成了一份程序；这些数字衡量本轮具体程序的表现。[被拒程序和原因](../runs/grounded_drawers_01/fresh/free/claude/STUDY_SCENE2_pick_up_the_book_and_place_it_in_the_right_compartment_of_the_caddy/rejection.json)

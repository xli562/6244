# 遇到歧义以后，再读一遍指令有用吗？

**两个旧故障都修到了 50/50。冻结后换 12 道新题，本轮新生成的 Codex 和 Claude 策略都救回 0 次，也没有反向丢分。** 换回上轮的策略、用同一个新 harness 跑同一批新题，Codex 救回 70 次，Claude 救回 112 次。收益全部集中在两道选碗的题上。能否涨分，取决于程序有没有把一个可以用原句和观测解开的歧义交给检查器。

## 先看两个旧故障

| 用来调试的指令 | 遇歧义就停 | 原程序关掉检查直接执行 | 回看原句，再用观测核对 |
| --- | ---: | ---: | ---: |
| 右侧咖啡壶放上炉（旧 Codex） | 0/50 | 50/50 | **50/50** |
| 后方黑碗放上盘子（旧 Claude） | 0/50 | 44/50 | **50/50** |

咖啡壶的 50 个初始提名都对，旧检查器只看到“两把壶”，所以不肯动。新检查器从原句里找到“右侧”，测量两把壶到场景里右侧位置标记的距离。摆放 0 中，一把离标记约 1.9 厘米，另一把约 23.5 厘米。

黑碗也用同一个办法。有 44 次通过复核保留了正确提名，另 6 次换到了真正靠近后方标记的碗。旧程序没有摘句函数，这两题实际走的是通用角色短语解析。实现里没有这两个任务名，也没有按壶或碗的编号选择。

## 哪些新题受益，哪些没有

**本轮新程序。** Codex 有 100 次真的回去读了原句，也摘对了相关短语，但依然有多个候选。拿右侧的书时，卡在“放到柜架”的目的地：场景提供上层、下层和顶面，指令没有指定哪一层。开顶层抽屉时，抽屉区域和柜子顶面都带 `top`；当前检查器还不能用“能否拉开”来区分它们。另有 50 次把整个柜子当成抽屉目标，属于类型不符。放行上述 150 次的原提名，最终成功 0 次。本轮 Claude 没有把并列候选交给复查。例如左碗入托盘，三份程序里有两份在全部 50 个摆放上直接结束，一次预览或动作都没有提交。

**和只看动作回执相比。** 新 Codex 从 869 到 962，多完成 93 次；Claude 从 1,183 到 1,063，少完成 120 次。新 Codex 的“遇歧义就停”也已达到 962。Claude 在左碗入托盘一题就从 150/150 降到 50/150。这些分差反映整份程序的差别，不能记作“回头重选”的收益。

**把上轮策略拿来复核。** 同样 12 道新题，左碗入托盘给旧 Codex 和旧 Claude 各救回 50 次；前方黑碗上盘分别救回 20 和 62 次。其余十题都没有救回。旧 Codex 的 70 次全部是原策略获准继续就能完成。旧 Claude 的 112 次里，有 97 次放行后原程序凭提名和自身重试也能完成，另 **15 次只有重选版成功**。同一道“前方黑碗”复用了调试题的房间和物体；“左碗入托盘”换了房间、方位和目的地。两者都仍属于选碗任务。右侧的书提供了一个反例：旧 Codex 有 50 次成功改选操作物体，目的地依然并列，整题还是 0 分。

**还有多少误拦？** 新程序的重选版终止在未解决角色上的有 150 次，旧程序的重选版有 200 次。逐一放行重放，**这 350 次里，能靠原程序继续做成的是 0 次**。计入“遇歧义就停”组，总共核对了 950 个终止回合，全部重现了原决策点。这里的零只回答“原程序继续跑能不能成”；还有多少失败可以靠更好的目的地选择、动作规划或抓取救回，这次实验没有给出上限。

## 测的是什么

- **只看动作回执。** 程序可以先读场景里的名字和坐标，自己选对象并执行。执行后能看到位移、抓起高度、离目标多远。
- **遇到歧义就停。** 程序额外声明每个角色的约束，执行前检查。若多个候选并列，就在这个决定前停下。
- **回看指令再选。** 与上一组使用同一份模型代码。新策略还可以提供一个函数，从原指令中摘出描述当前角色的短语。Harness 核查短语属于当前动作的物体还是目的地，再比较候选的名称或到可见参照点的实时平面距离。若模型没有给出可用摘录，且语法只确定一个角色短语，则用该短语复核。距离相差不超过 2 毫米仍算并列。空候选、非法角色类型与真正的并列分别记录。

本轮用 Codex（gpt-6-astra）和 Claude（claude-opus-5-5）各独立生成三份检查策略、三份回执策略，12 次调用全部编译通过。每份策略一次 CLI 调用，部署零调用；“停”和“重选”配对共享一次生成。三组均可读场景、选同样的抓法和技能，每个回合最多 500 个控制步。模型没有读到新题或评分器。只有“重选减去停”的差异可以归到这次执行机制；对比独立编写的回执版还混入了代码写法的差异。

先用历史上发生过误拦的两份原程序，各在原题的全部 50 个摆放上实测。再锁定 harness、初始策略、约束和抽样规则，从官方 LIBERO-90 固定版本抽取 12 道题。排除了 82 个旧任务、相同的标准化英文指令，并核对了全部状态哈希。600 个新状态互不重复，与 4,100 个历史状态均无完全相同的向量。抽样优先保留 6 道带方位词的题；另 3 道指令带连接词，实际是拿起再放下，还有 3 道普通指令。不同任务可以复用房间、物体和动作。[公开任务和数据](https://github.com/Lifelong-Robot-Learning/LIBERO/tree/8f1084e3132a39270c3a13ebe37270a43ece2a01/libero/libero)

每道新题的 50 个状态给每份策略跑一遍，每模型每组分母为 1,800。得分要求先满足官方成功条件，随后松手、抬手、等待共 40 步，条件仍成立。另将上一轮补充批次的全部 12 份程序原样部署到同一批新题，单独报告。这批只有通用的短语解析器，没有本轮新增的模型摘句函数。

## 怎样认定“误拦”

“救回”要求同一模型程序、同一状态，遇歧义即停版失败而重选版稳定成功。“反向丢分”是相反情况。仅仅少停一次、选出了唯一物体或抓起来了，均不算救回。

对最后停在未解决角色、且没有成功的回合，再从相同状态重放。只有再次看到同一个动作、候选、观测和剩余步数，才在这个决定上放行原提名，让程序走下去。之后若仍有未解决的角色，同样允许按原提名执行。最后达到稳定成功，才记为**已证实的误拦**。这个次数描述的是“继续使用原提名就能完成”的回合。若原提名也失败，可能还存在别的正确选法。策略根本没提出动作、或执行了但没放稳，也不计为误拦。

## 复核

从仓库根目录把证据包解到干净的检出目录。下列命令只汇总实际轨迹，无需调用模型或启动模拟器。逐摆放的成功、拦截和参照点距离保存在压缩的 JSONL 中。 `decisions.csv` 单列得救、反向丢分和仍被误拦的回合。

```bash
python -m zipfile -e reports/reselection_evidence.zip .
python harness/reselection/analysis/score.py
```

要重新跑物理仿真，可在另一份干净检出中展开同一证据包，将包内的 `runs/reselection_01/test.jsonl.gz` 和 `counterfactual.jsonl.gz` 移至该目录外以保留原始成绩。按 README 安装环境后，用该环境的 Python 依次运行 `harness/reselection/run.py test` 和 `harness/reselection/run.py diagnose`，最后运行上面的汇总命令。已有输出受覆盖保护。[证据包](reselection_evidence.zip)

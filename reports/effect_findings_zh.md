# 动作执行后再看一眼，能救回多少次？

**关炉的 300 个调试回合救回了 252 次。换成六道没调过的新题，两个模型各跑 900 个回合，救回 0 次，也没有反向丢分。** 这两种结果的区别在于，关炉时能很快看到旋钮没按预期转动，还有时间换动作；放置技能往往到很晚才交回控制权。

## 三个版本的稳定成功次数

| 范围 | 模型 | 只有动作回执 | 旧版 harness | 加动作后反馈 | 经重放证实救回 |
| --- | --- | ---: | ---: | ---: | ---: |
| 关炉调试，每格 150 次 | Codex | 0 | 0 | 108 | 108 |
| 关炉调试，每格 150 次 | Claude | 0 | 0 | 144 | 144 |
| 六道新题，每格 900 次 | Codex | 224 | 209 | 209 | 0 |
| 六道新题，每格 900 次 | Claude | 207 | 207 | 207 | 0 |

每道题有 50 个不同摆放，每个模型独立生成三份程序，三份程序都用同一批摆放。旧版保留动作前的对象核对、能力查询和缺失提案重试。旧版与新版的主程序相同，普通回执可触发的补救也相同。仅回执组可以独立改写程序。三组均可使用相同的抓取、放置和关节控制动作，并遵守相同的调用和控制步预算。

## 关炉怎么救回的

以 Codex 第一份程序的摆放 0 为例，初次推压前后，旋钮均位于全行程的约 47%。机械臂动了，但关节没有往关闭端走。模型写的处理函数看见这个差值，改用夹爪接触活动部件，沿测得的关节轴转动，接近端点时减速，减小松手反弹。技能使用仿真中可观测的碰撞几何、关节轴、位置和行程，通过夹爪施力。程序里没有按炉子、旋钮名称或题号选择动作的分支。

252 次救回中，**251 次**的第一次推压几乎没改变旋钮位置，**1 次**把它往反方向推了。逐一回放，原动作结束时官方“已关”条件仍为假，改变动作后变成真，松手后仍然成立。用相同的触发时机和步数上限，让程序重复原动作，这 252 次全都失败。Codex 新版曾有 111 次达到瞬时成功，其中 108 次松手后保持；Claude 的 144 次都保持了。

## 为什么新题没涨

- **176 个回合看到了偏差并重试，全部发生在酒瓶任务。** 酒瓶入碗 80 次、酒瓶上盘 96 次，程序都选择重新对齐再放。重试开始时剩余步数的中位数是 36，范围是 22 至 219。176 次都用完了 500 步，瓶子和目标的水平距离仍大于 4.5 厘米。
- **有些技能交回控制权时，预算已经用光。** 把奶油奶酪放上架子的 300 个新版回合，第一次放置就用掉全部 500 步。另一个例子是把奶酪推到炉前：100 个回合没有动，另外 200 个发出了动作，但当前的观测规则没有为这种相对位置的推压定义预期变化。
- **已有的成功也保住了。** 三组在派生题“番茄酱放上盘子”均为 150/150。单看五道公开原题，Codex 回执、旧版、新版分别为 74、59、59 次，Claude 均为 57 次，分母都是 750。六题中没有任何一个摆放从旧版成功变成新版失败。

## 怎么判断真是反馈救回来的

旧版和新版共用同一份模型代码、初始摆放和物理技能。两者都能按普通动作回执主动补救。新版还会在一次技能实际执行后，将动作前后的观测立即交给模型写好的处理函数。每回合最多两次额外调整，全部计入原有的 500 个控制步。仅回执版由同一个模型独立编写，沿用其原来的回执策略，也能使用相同的关节动作和抓法。每个模型为检查策略和回执策略分别独立生成三次，每份在各自上一轮策略上再用一次 CLI，本轮共 12 次。测试时三个版本均为零模型调用。

要把一次成功记成“反馈救回”，先要求同一份策略旧版失败、新版稳定成功，且首次干预之前两条轨迹的提案所绑定的角色、关节或物体观测、手部位移和剩余步数一致。随后独立重放，要求重现新版全部动作观测和调整，并由评分器核实：所针对的子目标在原动作结束时仍为假，调整前仍为假，调整后变成真。评分器只在这个离线核验中查看子目标，策略运行时只能读取场景观测。最终成功还须经松手、抬手和等待共 40 步复查。

这里另算两件事。第一，是否属于**原动作几乎没有效果**：夹爪至少移动 1 厘米，但可动关节变化不足全行程的 2%，或被搬物体位移不足 1.2 厘米且距目标仍超过 4.5 厘米。向反方向移动和已有进展但没到位分别统计。第二，在同样预算下保留触发时机、把调整替换为**重复原动作**，检查是否也能完成，分辨重复尝试与改变动作的贡献。

## 测试集从哪里来

冻结代码、模型程序、预算和初选规则后，读取公开 LIBERO-Pro 固定版本中的 80 份任务或物体变化定义。用本项目 109 道历史任务的目标和已记录的放置动作排重，同一物体类别到同一目的地类别的任务从严合并，颜色、实例编号和换个说法都不能单独算新任务。还检查了多步骤指令，删除了“打开顶层抽屉再放入奶酪”：这道题的评分器只要求放入，但原句包含练过的开抽屉子任务。[LIBERO-Pro 官方数据集](https://huggingface.co/datasets/zhouxueyang/LIBERO-Pro/tree/c86fc3b8293185a6f373677018ff3e37f8391602)

最终保留五道公开题，另用官方 LIBERO 场景中已存在的番茄酱和盘子构造了一道新放置题。这个派生题单列来源。每题用原模拟器重置并冻结 50 个尚未成功的全新摆放，检查 300 个新状态互不重复，也不与 5,450 个历史状态向量重复。使用本项目冻结的状态观测和控制器，成绩适用于这六题及这些摆放。[原始 LIBERO 场景](https://github.com/Lifelong-Robot-Learning/LIBERO/tree/8f1084e3132a39270c3a13ebe37270a43ece2a01/libero/libero/bddl_files/libero_90)

## 复核

在干净检出中展开证据包，即可用 Python 标准库重算全部配对结果。包里保留了动作前后观测、每次调整、固定任务与初始状态、配对结果和独立评分器重放。完整物理重放沿用上一轮的冻结策略和 LIBERO 环境。[证据包](effect_evidence.zip) · [反馈实现](../harness/effect/feedback.py) · [物理动作](../harness/effect/motion.py) · [归因核验](../harness/effect/analysis/causal.py)

```bash
python -m zipfile -e reports/effect_evidence.zip .
python harness/effect/analysis/score.py
```

要重新跑冻结版的物理对照，请在另一份干净检出中展开项目已有的 `affordance_evidence.zip`、`reselection_evidence.zip` 和本轮证据包，安装 LIBERO，并把本机的 `third_party/libero-config/config.yaml` 复制到 `runs/effect_01/assets/config.yaml`。先把已归档的 `test.jsonl.gz`、`repeat.jsonl.gz`、`test_causal.jsonl.gz` 移到其他目录保存，再用安装了 LIBERO 的 Python 顺序运行下列入口。前两条都检查文字复核名单，仅执行最终六题。

```bash
"$LIBERO_PY" harness/effect/analysis/heldout.py test
"$LIBERO_PY" harness/effect/analysis/heldout.py repeat
"$LIBERO_PY" harness/effect/analysis/causal.py test
python harness/effect/analysis/score.py
```
